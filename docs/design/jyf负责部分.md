# JYF 负责部分

人员 B（JYF）负责故事 1–3、5、7、15、25–31。本稿描述这些故事的实现方案，故事 25 只涵盖发帖提交。类图、状态图、时序图和跨模块约定见 [M2 设计初稿](M2-板块及帖子管理-设计初稿.md)和 [M3 设计初稿](M3-帖子互动-设计初稿.md)。

## 1 按板块浏览（FR-06）

**数据模型**

- 话题板块 `Board` 保存 `id`、`name`、`status` 和 `sortOrder`。帖子通过 `boardId` 归属板块。
- 公开列表项包含帖子 ID、标题、板块、发布时间和公开作者标识。列表按需取点赞数和可见评论数。

**接口或流程**

- `GET /boards` 返回启用板块，按排序值和 ID 升序，供板块入口与发帖选项共用。
- `GET /posts?boardId=…` 返回对应板块的可见帖，按发布时间和 ID 倒序分页。

**关键校验**

- 进入板块和切换板块均以本次请求的 `boardId` 查询。快速切换时，前端丢弃上一个板块的迟到响应。
- 板块存在但没有可见帖子时返回成功与空数组。选中的板块已停用或不存在时，提示刷新板块列表。

**验收场景**

- 在两个板块各创建可见帖，再隐藏其中一帖。切换时只显示选中板块的可见记录。对空板块和停用板块分别验证空列表与不可选提示。

## 2 查看帖子详情（FR-07）

**数据模型**

- 公开详情包含标题、正文、发布时间、板块、公开作者、评论开关及互动统计。评论只取仍可见的记录。
- 登录用户的 `liked`、`favorited` 由本人关系得到。

**接口或流程**

- `GET /posts/{id}` 先验证父帖可见，再读取评论、计数与本人状态。帖子和可见评论按同一读取快照组装。
- 详情首屏可带首批评论，后续按约定的评论分页参数读取，后续请求继续校验父帖状态。

**关键校验**

- 帖子不存在、已下架或已删除时统一返回 `404`。前端清除旧详情，直接请求旧链接也拿不到正文或评论。
- 评论开关为关闭时仍展示已有可见评论。帖子公开数据只采用白名单字段。

**验收场景**

- 分别使用游客、登录学生和旧链接打开正常帖、关评帖及失效帖。核对正文、评论、公开字段与状态码。

## 3 搜索与板块筛选（FR-08）

**数据模型**

- 关键词匹配 `Post.title` 或 `Post.body`，可选择附加板块条件。结果复用列表摘要。
- 首版使用带绑定参数的数据库查询，按发布时间和 ID 倒序分页。数据增长后结合 NFR-08 评估全文检索。

**接口或流程**

- `GET /posts?q=…&boardId=…` 接收关键词和可选板块。去掉关键词首尾空白，清空关键词时回到常规列表。
- 查询条件为可见性、可选板块、以及标题或正文匹配三者同时成立。

**关键校验**

- 查询参数按字面匹配处理通配符，输入不会改写查询条件。选中板块失效时提示改选。
- 列表、详情和搜索读取同一数据源。编辑成功后显示新标题和正文，删除或下架后结果不再返回。

**验收场景**

- 分别验证标题命中、仅正文命中、其他板块命中、无匹配以及内容失效后再次搜索。

## 5 点赞与取消点赞（FR-13）

**数据模型**

- `PostLike(postId, userId, createdAt)`，`(postId, userId)` 唯一。点赞数按该帖的关系数量统计。

**接口或流程**

- `PUT /posts/{id}/like` 设置为已点赞，`DELETE /posts/{id}/like` 设置为未点赞。返回 `liked` 与 `likeCount`。
- 服务端以当前用户处理写入，并在同一帖子事务内校验可见性、改变关系及读取结果。前端对同一帖子顺序发送操作。

**关键校验**

- 未登录返回 `401`；目标不可见返回 `404`。重复 PUT 沿用已有关系，重复 DELETE 允许零行。
- 并发采用唯一约束防重。点赞状态与数量按服务端响应更新，刷新再从保存的关系读取。

**验收场景**

- 同一账号并发发送两次 PUT，只增加一次。重复取消后计数一致。下架帖子后直接请求点赞，验证操作被拒绝。

## 7 收藏帖子（FR-23）

**数据模型**

- M5 保存 `Favorite(id, postId, userId, createdAt)`，`(postId, userId)` 唯一。
- 收藏列表项组合收藏关系与 M2 公开摘要。失效项暂定只返回必要标识、收藏时间和失效状态，供本人移除。

**接口或流程**

- `PUT /posts/{id}/favorite` 在同一事务内先校验帖子可访问，再创建本人收藏。重复请求沿用已有关系。
- `DELETE /posts/{id}/favorite` 按会话用户移除关系。`GET /me/favorites` 分页获取本人收藏并批量读取公开摘要。

**关键校验**

- 收藏与公开列表使用同一可见性规则，原帖失效后不能新增收藏。取消操作在原帖失效后仍可执行。
- 失效收藏不返回帖子标题、正文或作者。接口不会按客户端指定的用户查询收藏。

**验收场景**

- 验证收藏后刷新、重复收藏、原帖下架后的占位提示、从列表移除失效收藏，以及两账号的收藏列表隔离。

## 15 查看自己发布的帖子（FR-10）

**数据模型**

- 管理列表以 `Post.authorId` 归属过滤。条目包含帖子 ID、标题、板块、发布时间和状态，公开状态与本人管理状态独立显示。

**接口或流程**

- `GET /me/posts` 从会话取用户 ID，按 `publishedAt DESC, id DESC` 排序分页。条目按状态显示可用操作。
- 点击编辑或删除仍由对应写接口重新校验所有者和当前状态。

**关键校验**

- 未登录返回 `401`。伪造 `authorId` 不能读取他人列表。没有本人帖子时返回空集合。
- 下架或删除记录保留管理状态，公开入口继续按公开可见性规则处理。

**验收场景**

- 用两个账号分别发帖，并将其中一帖下架。验证两个列表互不混入、排序稳定、失效状态正确。

## 25 发布失败后安全重试（NFR-04）

**数据模型**

- 首次发送时保存账号范围内的草稿、原请求及幂等键。`PostSubmission` 记录 `authorId`、`idempotencyKey`、`payloadHash` 和 `postId`。
- `(authorId, idempotencyKey)` 唯一。成功创建时在同一事务内保存帖子与幂等记录。

**接口或流程**

- `POST /posts` 携带 `Idempotency-Key`。同键同摘要回放成功并返回原帖 ID，同键异摘要返回 `409`。
- 断网或响应丢失时前端保留原请求并显示“结果待确认”。网络恢复后按原账号、原键和原内容重试。
- 明确未创建的校验失败允许回到编辑态。用户修改后以新的提交尝试发送；结果仍未知时只重发原请求。

**关键校验**

- 同键并发由事务及唯一约束保证至多一条。冲突回滚后回查已提交记录，不把尚未确认的结果展示为成功。
- 已提交帖子后来下架或删除时仍可确认原提交成功，查看旧链接继续接受公开权限校验。

**验收场景**

- 分别模拟请求未送达、已提交但响应丢失、同键并发以及同键异载荷。确认数据库记录数、返回 ID 和前端反馈。

## 26 发布帖子（FR-09）

**数据模型**

- `Post` 保存作者、标题、正文、板块、发布时间、可见状态和评论开关。新帖为 `VISIBLE`，默认允许评论。

**接口或流程**

- `POST /posts` 接收 `boardId`、`title`、`body`。服务端取会话用户、校验发帖权限和启用板块。
- 数据验证成功后事务写入帖子和幂等记录，提交后返回 `201` 及 `postId`，前端导航到详情。

**关键校验**

- 标题、正文去掉首尾空白后必填。账号受限时返回 `403` 并显示适用理由，停用板块拒绝新帖。
- 发布与停用同一板块按数据库锁排序。提交失败保留草稿；重复发送沿用故事 25 的规则。

**验收场景**

- 验证正常发布后对应板块和详情立即可读，再测试空白内容、停用板块、无会话和发帖权限受限。

## 27 开启或关闭评论（FR-15）

**数据模型**

- `Post.commentsEnabled` 记录是否允许新增评论，帖子可见状态另存。历史评论不随开关变化。

**接口或流程**

- `PUT /posts/{id}/comment-setting` 接收布尔字段 `commentsEnabled`。按会话用户确认发帖人身份，锁定帖子并写入目标状态。
- 成功返回当前开关。前端同步表单状态，后端发表评论接口也独立检查该值。

**关键校验**

- 目标必须是本人可见帖子。重复写入同一目标状态结果一致。关评与新增评论使用同一父帖锁，先提交者决定并发结果。
- 已有可见评论继续可读，评论作者仍可撤回自己的评论。重新开启后恢复新增能力。

**验收场景**

- 用作者和另一账号分别尝试修改。验证关闭、历史评论展示、新增被拒绝、重新开启，以及并发关评和发表评论。

## 28 编辑自己的帖子（FR-11）

**数据模型**

- 允许编辑 `title`、`body`、`boardId`。保留帖子 ID、作者、发布时间和已有点赞、收藏与评论关系。

**接口或流程**

- `PATCH /posts/{id}` 只接收允许修改的字段。迁板时先锁目标板块再锁帖子，锁内重新校验归属与状态。
- 成功保存后返回更新摘要。列表、搜索和详情读取更新后的业务记录。

**关键校验**

- 标题、正文仍须非空。目标板块停用时拒绝迁入。找不到帖子或不属于本人时返回 `404`。
- 已下架、已删除状态拒绝编辑。接口不会从客户端接受作者、可见状态或互动统计，不能借更新恢复公开。

**验收场景**

- 修改标题和板块后，从新旧板块与搜索分别核对，确认互动保留。用他人账号和下架记录验证写入被拒绝。

---

## 29 删除自己的帖子（FR-12）

**数据模型**

- 作者删除时将现有帖子标记为 `DELETED`，保留点赞、收藏和评论关系。

**接口或流程**

- 作者确认后调用 `DELETE /posts/{id}`。服务端锁定帖子，校验归属，并在事务中写入删除状态。
- 提交成功返回 `204`。前端从公开列表移除条目，管理列表显示删除状态。

**关键校验**

- 不存在或非本人时返回 `404`。本人重复删除返回相同操作结果。
- 删除状态生效后，公开详情、列表、搜索停止提供正文，新增互动按失效处理。已有收藏可由收藏人移除。

**验收场景**

- 删除一条有评论和收藏的帖子，复查公开入口、旧链接、互动接口和收藏页，再用他人账号尝试删除。

## 30 发表评论（FR-14）

**数据模型**

- `Comment` 保存 `id`、`postId`、`authorId`、`body`、`status` 与 `createdAt`。成功新增初始状态为 `VISIBLE`。

**接口或流程**

- `POST /posts/{id}/comments` 接收正文。校验会话、账号评论权限和正文，锁定父帖后检查可见状态和开关。
- 事务写入后返回 `201` 及新评论与 `commentCount`。

**关键校验**

- 空白正文 `400`、未登录 `401`、账号受限 `403`、父帖不可访问 `404`、关闭评论 `409`。
- 关评、隐藏或删除父帖与发表评论用同一父帖锁裁决。写入失败时评论列表和计数均保持原状。

**验收场景**

- 验证正常评论、空白正文、关评后直接调用接口、账号受限、父帖下架，并核对刷新评论列表与计数。

## 31 删除自己的评论（FR-16）

**数据模型**

- 作者撤回时将评论状态更新为 `DELETED`。统计只计 `VISIBLE` 评论，保留父帖关联。

**接口或流程**

- `DELETE /posts/{postId}/comments/{commentId}` 先锁父帖再锁评论，检查两者归属匹配及评论作者。
- 父帖可见时返回更新后的评论数；父帖失效时仅返回 `204`，评论内容与统计继续按父帖控制。

**关键校验**

- 删评独立于评论开关，评论关闭后仍可撤回。非本人、评论不存在或父帖 ID 不匹配时统一返回 `404`。
- 重复删除沿用已有状态，计数不会重复扣减。隐藏评论再由本人删除，也不会再次减少可见数量。

**验收场景**

- 验证关评后本人删除、他人尝试删除、错误父帖、已隐藏评论撤回和重复删除，再刷新核对列表与计数。
